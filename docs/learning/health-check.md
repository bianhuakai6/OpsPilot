# 健康检查：M0 学习记录

## 它解决什么问题？

健康检查为运行环境提供一个低成本的服务状态入口。容器编排或发布脚本可以通过 HTTP 请求判断进程是否能够响应，而不需要理解业务接口。

## 本项目在哪里使用？

当前实现位于 `app/main.py` 的 `GET /healthz`。它只确认应用进程和 HTTP 路由可用，不检查 MySQL、Redis 等外部依赖。

## 为什么第一版不检查数据库？

M0 还没有数据库依赖。即使后续加入数据库，也要区分：

- **liveness**：进程是否应该被重启；
- **readiness**：实例是否可以接收流量。

把依赖故障直接当成进程故障，可能导致实例反复重启，扩大故障影响。因此后续会分别设计 `/healthz` 和 `/readyz`。

## 如何验证？

在项目根目录运行：

```text
python -m pytest
```

启动服务后访问：

```text
python -m uvicorn app.main:app --reload
```

然后请求 `http://127.0.0.1:8000/healthz`，预期响应为：

```json
{"status":"ok"}
```

## 面试表达

当前健康检查是进程级检查，不伪装成依赖级健康检查。后续接入数据库和 Redis 后，会根据发布和流量接收需求拆分存活探针与就绪探针，避免依赖故障导致无意义的重启风暴。
