# M2 本地依赖与可观测性验收记录

## 验收范围

本记录验证本地运行链路：Docker Compose 依赖、FastAPI 完整模式、健康与就绪接口、自动化巡检、只读压测和自动化测试。它证明当前开发环境的功能闭环，不等同于生产可用性认证。

## 本次结果

验收日期：2026-09-28（本地时区 Asia/Shanghai）。

- Docker Compose：MySQL、Redis 容器均为 `running` 且健康状态为 `healthy`。
- `GET /healthz`：返回 `{"status":"ok"}`。
- `GET /readyz`：返回 `ready`，MySQL 与 Redis 均为 `connected`。
- `POST /api/v1/inspections/run`：整体状态为 `pass`；进程、配置、指标注册表/新鲜度、磁盘、内存、MySQL、Redis 检查均通过。
- 轻量压测：对只读 `GET /healthz` 运行 2 秒、2 并发；376 次请求，0 失败，约 187.88 req/s，P50 4.92 ms，P95 29.24 ms。
- 自动化测试：设置 `OPSPILOT_RUN_MYSQL_TESTS=1` 后运行 `pytest -q`，36 passed。运行前检查 `activity-001` 的预约和幂等记录均为 0；测试结束再次确认均为 0，未改变已有业务记录。
- Compose 配置与启动脚本语法检查通过；Windows PowerShell 的启动路径已用完整模式实际启动，并保持前台可用。

压测数据属于一次本机样本，受当时 CPU、后台任务、日志输出、服务版本和测试持续时间影响，不能作为容量上限或 SLO。可用 [M2 压测基线](m2-load-test.md) 在相同条件下重复比较。

## 已知边界

- 当前压测工具是本机线程池生成负载，不是独立压测集群，也不覆盖长时间稳定性和真实用户流量模型。
- 当前巡检是手动/脚本触发，不包含定时调度、外部告警通知或自动修复。
- 当前仪表盘展示运行状态和巡检结果；压力测试页已支持固定只读目标、受限参数、实时轮询、延迟曲线和停止操作。
- 当前完整模式的 API 进程仍由本地 Python/Uvicorn 运行，MySQL/Redis 由 Docker Compose 托管；应用容器化尚未作为已完成能力宣称。
