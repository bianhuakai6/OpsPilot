# OpsPilot 校招简历项目稿

> 用途：提前熟悉项目的完整表达，并作为后续开发验收清单。`[已验证]` 才能直接写成简历成果；`[进行中]` 和 `[目标]` 是项目计划，完成并留下证据后再改成已验证。

## 项目标题

**OpsPilot｜面向在线服务的可观测、自动巡检与 Agent 辅助运维平台**

技术栈：`Python / FastAPI / Uvicorn / MySQL / Redis / Docker / Docker Compose / Pytest / Prometheus Metrics / GitHub`

## 项目概述

以在线资源预约服务作为可控业务负载，构建覆盖“业务运行、发布交付、健康检查、自动巡检、压力验证、故障恢复和 Agent 辅助分析”的本地优先运维平台。业务服务本身不是最终目标，重点是验证一个在线服务从开发到运行、观测、故障响应和复盘的完整生命周期。

## 简历成稿（目标完整版）

### 业务与系统实现

- 基于 FastAPI 设计活动查询、资源预约、容量约束和重复预约处理接口，使用 MySQL 持久化业务数据，并结合 Redis 实现缓存/运行状态相关能力。[已验证：M1/M2]
- 通过配置边界、统一错误响应和数据模型约束，保证接口行为可测试、可解释；使用 Pytest 覆盖核心业务、接口和发布相关验证。[已验证：当前测试集；持续扩充]

### 可观测性与主动巡检

- 实现 `/health` 与 `/readyz`，分别用于区分进程存活和依赖就绪状态；检查 MySQL、Redis 连通性并返回结构化结果。[已验证]
- 建立结构化日志和 Prometheus 风格指标，采集请求量、错误数、请求耗时及业务计数，用于定位异常请求和判断服务退化。[已验证：基础能力]
- 设计只读自动巡检流程，覆盖服务进程、依赖连通性、配置完整性、磁盘/内存阈值、发布状态和指标新鲜度；每项输出 `check_id`、状态、严重级别、证据、检查时间和建议动作。[已验证：基础巡检；持续扩展]
- 提供运维控制台和可视化压测页面，展示服务状态、巡检结果、并发、吞吐量、失败率及 P50/P95 延迟。[已验证：本地页面]

### 容器化交付与可靠性

- 使用 Docker Compose 编排 API、MySQL 和 Redis，区分原生开发模式与完整容器交付模式，避免端口和运行边界混淆。[已验证]
- 实现“容器内测试 → 构建带 Git SHA 的版本镜像 → Compose 部署 → `/readyz` 就绪校验”的本地发布链路；测试失败时阻断部署。[已验证：M3 基础]
- 记录版本、Git SHA、镜像、发布时间和发布结果，模拟健康检查失败并保留诊断信息；使用上一个已验证镜像执行回滚和恢复验证。[进行中：M3]
- 设计 Redis、MySQL、API 进程和流量突增等故障演练，记录故障注入、观测证据、恢复动作、恢复时间和复盘结论。[目标：M4]

### Agent 与工程化协作

- 使用 Agent 辅助需求拆解、代码实现、测试设计、故障定位和中文知识文档沉淀；通过 Git 提交、自动化测试和本地验收约束生成内容质量。[已验证：开发协作流程]
- 规划只读 Agent 运维能力：Agent 基于日志、指标、巡检和发布记录生成根因候选、风险说明和 Runbook 建议，涉及高风险操作时必须人工审批并留下审计记录。[目标：M5]
- 规划提交触发测试、镜像构建、发布验证和失败阻断的 CI/CD 流程；正式接入后只声明实际执行过的流水线结果。[目标：M3/M5]

## 面试讲解主线

1. **为什么需要这个项目？** 只写业务接口无法体现 SRE 能力，因此用一个简单在线服务承载完整的交付、观测和恢复链路。
2. **一次请求怎么走？** 浏览器/客户端请求 FastAPI，服务校验参数并访问 MySQL/Redis，返回响应，同时产生日志和指标。
3. **怎么知道服务是否健康？** `/health` 只说明进程存活；`/readyz` 还检查 MySQL、Redis 等依赖是否可用；自动巡检进一步发现配置、资源和指标新鲜度风险。
4. **怎么发布？** Git 提交确定版本，Docker 在容器内运行测试，构建带 Git SHA 的不可变镜像，Compose 启动服务，再用就绪检查验收。
5. **发布失败怎么办？** 保留失败证据，不把未就绪版本当作成功发布；选择上一个已验证镜像回滚，再验证服务和依赖恢复。
6. **Agent 做什么？** Agent 先读取结构化上下文并给出可验证建议；高风险动作必须人工确认，不能把模型输出直接当作生产命令。

## 当前不能直接声称的内容

- 尚未完成的回滚演练不能写“已实现自动回滚”。
- 尚未接入流水线不能写“已实现完整 CI/CD”。
- 尚未部署 Kubernetes 或云环境不能写“已上云/生产运行”。
- 只停留在计划或配置文件中的 Agent 工具不能写“已实现自动故障修复”。
- 压测页面的成功率为实验结果，不代表生产 SLA；必须说明实验条件和局限性。

## 最终简历压缩版（完成 M3/M4/M5 后使用）

> **OpsPilot｜面向在线服务的可观测与 Agent 辅助运维平台**（个人项目）  
> 基于 FastAPI、MySQL、Redis 构建在线资源预约服务，设计容量约束、幂等处理和统一错误响应；实现健康/就绪检查、结构化日志、指标采集、自动巡检、运维控制台及可视化压力测试，支持通过 P50/P95 延迟、吞吐量和失败率分析服务质量。

> 使用 Agent 汇总日志、指标、巡检和发布上下文，生成根因候选与 Runbook 建议，并以人工审批、权限边界和审计记录控制高风险操作。
